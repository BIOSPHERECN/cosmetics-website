## 一 · 架构定案

| 项 | 定案 | 理由 |
|---|---|---|
| 托管 | **Cloudflare Workers**(不迁 PHP 服务器) | 前台已跑通;外贸站要全球边缘;零运维 |
| 数据库 | **D1**(`bohui-cms-v2`) | 已有 13 表、上千行内容 |
| 对象存储 | **R2**(桶 `bohui-photo`) | 待开通;未开通期间用 D1 直存兜底 |
| 前台框架 | **Astro 7 SSR** | 已上线,不重做 |
| 后台 | **Payload CMS 3** | 官方有 `db-d1-sqlite` / `storage-r2` / `plugin-multi-tenant`,均 3.88.0 |
| 视觉 | **复刻层 marvis**,默认极简白 | 创始人已认可方向 |
| 语种 | 简中 · 英 · 日(**繁体已移除**) | 后续可加,架构已支持 36 语 |

**否决的方案与理由**(写下来免得重提):
- Craft CMS / Statamic:成熟度最高、买断制,但**是 PHP**,要换整套栈、买服务器、前台重做 —— 代价不值。
- Sanity / Contentful:**按席位按月收费**,5 条产品线长期成本高,且数据不在自己手里。
- 继续手搓后台:表格筛选排序批量、富文本、版本回滚、权限,成熟系统打磨十几年,手写追不上。

## 二 · 后台迁移:分两期,带验证关卡

### 一期 · 现有后台补到「能用」(不等 Payload)

理由:Payload 验证要时间,而运营现在就要改内容。一期做的每一件事在二期都不浪费 —— 数据模型和权限模型是共用的。

| # | 事项 | 验收标准 |
|---|---|---|
| 1.1 | **一域名一后台** | 账号绑定站点后,改地址栏也查不到别站数据 |
| 1.2 | 图片选择器 | 所有图片字段点一下从媒体库选,不手打路径 |
| 1.3 | 询盘邮件通知 | 前台提交后 60 秒内收到邮件,含配方号与后台直达链接 |
| 1.4 | 配方导入 | 已完成(实测脏数据 7 项全按预期处理) |

### 二期 · Payload 迁移

**验证关卡(不通过就停在一期,不硬上)**:
起一个空 Payload → 接 D1(`db-d1-sqlite`)→ OpenNext 部到 Workers → 能登录、能存一条记录、能上传一张图。
**这一步不通,二期作废,一期继续加固。**

验证通过后的迁移顺序:

| # | 事项 | 验收标准 |
|---|---|---|
| 2.1 | 13 张表 → Payload collections | 现有内容零丢失导入 |
| 2.2 | multi-tenant 插件按域名分租户 | 5 个域名各自独立后台 |
| 2.3 | 前台改读 Payload API | 5 站 30 页渲染与现在一致 |
| 2.4 | 旧后台下线 | 并存一周无问题后再下 |

## 三 · 数据与权限定案

### 账号归属
- `users.site_id` 为空 = **集团管理员**(创始人),可跨站
- `users.site_id` 有值 = **站点运营**,只能管那一个站,数据层就查不到别站

### 内容归属
所有内容表已带 `site_id`:`pages` · `products` · `inquiries` · `studio_sessions` · `skin_sessions`
**例外**:`formulas`(配方库)与 `providers`(模型舰队)是**集团共用**,只有集团管理员可改。

## 四 · 页面清单(5 站 × 6 页 = 30 页)

每页的版块序列**写死在这里**,不再一页一议。

### 首页
```
banner(超大首屏图)→ matrix(品类矩阵)→ process(服务流程)
→ bases(生产基地)→ certs(资质)→ inquiry(询盘引导)
```

### 能力与服务 / 产品品类 / 质量合规 / 关于我们
```
页面页头(h1 + SEO 描述)→ prose(正文)→ 该页专属版块 → inquiry
```

### 联系询盘
```
页面页头 → form(询盘表单)→ inquiry
```

### 独立页(不走数据库渲染,但走同一外壳)
- `/[lang]/skin/` —— AI 肌肤检测
- `/[lang]/studio/` —— AI 共创工作台
