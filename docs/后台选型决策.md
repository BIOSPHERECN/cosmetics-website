## 一、先说清楚需求的真正难点

「像 WP 那样的后台」听起来是一件事,拆开其实是五件,难度天差地别:

| 能力 | 难度 | 说明 |
|---|---|---|
| 改文字 | 低 | 任何 CMS 都能做,连纯 git 方案都行 |
| **上传图片并管理** | **高** | 批量拖拽、全局资产库、复用、裁剪、派生尺寸 —— 这是创始人最在意的一环 |
| **四语同屏编辑** | **高** | 五站 × 四语,翻译机制若不内置,运营会疯 |
| 五站共用一个后台 | 中 | 需要多集合或多租户建模 |
| 权限与修订历史 | 中 | 多人协作后必需,出事能回滚 |

**判据**:选型的胜负手是「图片管理」和「多语言」,不是「能不能改文字」。

## 三、三个真实候选的关键事实(查自官方文档)

### A 案 · Directus v12

- **数据库**:PostgreSQL / MySQL / **SQLite** / MSSQL / MariaDB 等全支持。
  → **用 SQLite 就不需要单独的数据库服务器**,部署复杂度大降。
- **规格要求**:最低 0.25 vCPU / 512MB,官方建议 1 vCPU / 2GB。
- **文件存储**:存储适配器模式,可挂本地目录,也可接 S3 兼容存储(即可用 Cloudflare R2)。
- **媒体库**:批量上传、全局资产搜索、跨内容复用、内置图片变换。**这是最像 WP 媒体库的一个。**
- **多语言**:翻译机制内置,四语可同屏编辑。
- **权限 / 修订历史**:内置。
- **需要**:一台常驻小服务器 + Docker。

### B 案 · Keystatic(@keystatic/astro v5.2.0)

- 后台长在站点里(`/keystatic` 路由),内容与图片直接提交进 Git 仓库。
- **图片**:`image` 字段存到仓库指定目录(如 `public/images/...`),后台是文件选择器。
  云端选项要走 Keystatic Cloud(第三方服务)。
- ⚠️ **关键发现**:GitHub 模式**需要 Node.js API 路由**,即需要 SSR 支持,
  并且要**创建一个 GitHub App**。所以「零服务器」并不成立 ——
  在 Cloudflare Pages 上要额外启用 Functions/SSR 适配器。
- 多语言靠自己建模,无内置翻译机制。
- **优势**:无月度服务器成本,内容随代码一起版本化。

### C 案 · Payload v3.87.1

- 是一个 **Next.js 应用**,需要 Next 运行时。
- **数据库**:PostgreSQL 或 MongoDB(**不支持 SQLite**)。
- **文件存储**:需接 S3 / Azure / GCS / Vercel Blob 等适配器(R2 走 S3 适配器可行)。
- 可部署到 Cloudflare Workers(官方有教程)。
- **代价**:Next 运行时 + Postgres + 对象存储 = **三个活动部件**,
  而 Directus + SQLite 只有**一个**。后台功能是强,但我们并不需要它的应用级能力。

## 四、结论与推荐

### 推荐:**A 案 Directus + SQLite**

理由,按重要性排序:

1. **胜负手在图片管理,Directus 赢得最干脆。** 真媒体库(批量拖拽、全局搜索、跨内容复用、
   内置图片变换)正是创始人「自己上传图片自行修改」的核心诉求;
   Keystatic 的图片是「提交进仓库的文件」,没有资产库概念,这恰是它的短板。
2. **四语内置翻译。** 五站 × 四语 = 20 份内容,没有内置翻译机制,运营成本会失控。
3. **活动部件最少。** SQLite 让它变成「一个 Docker 容器 + 一个文件」,
   比 Payload 的三件套好维护一个数量级 —— 而我们不需要 Payload 的应用能力。
4. **成熟度够。** 37,275★、v12、每日提交,不是玩具。

### 诚实说清代价

- **唯一新增成本:一台常驻小服务器。** 1 vCPU / 2GB 即可,市面价约每月数美元级。
  这是全线目前唯一的月度支出(5 个站本身在 Cloudflare Pages 上是免费的)。
- 需要有人会基本的 Docker 运维(启停、备份 SQLite 文件、升级镜像)。
  备份很简单:SQLite 就是一个文件,加上 R2 的媒体目录。

### 什么情况下改选 B 案 Keystatic

如果创始人的判断是「**绝不接受任何月度服务器成本**」,那就选 Keystatic,
但必须接受两条:图片管理弱(没有资产库),多语言要自己搭。
我不会假装这两条不存在。

## 五、拍板后的落地路径(A 案)

内容契约已经按这条路设计好了 —— `packages/core/src/types.ts` 里的 `HomeContent`
就是「后台导出 JSON → 前端渲染」的接口,**上层页面一行都不用改**。

1. 一台小服务器起 Directus(Docker + SQLite),媒体存储接 Cloudflare R2
   ⚠️ 碰 R2 前必须先走 `zero-r2-move` skill —— 铁律:绝不事后 copy 搬图(曾一天烧 $40)。
2. 在 Directus 里按 `types.ts` 的形状建集合(站点 / 首页内容 / 产品 / 认证),开四语翻译。
3. 把现有 `packages/core/src/content/*.ts` 的内容导入进去(一次性脚本)。
4. `content/index.ts` 从「读本地 TS」改为「构建时拉 Directus JSON」——**只改这一个文件**。
5. 后台点发布 → webhook 触发 GitHub Actions → 6 站自动重建上线(流水线已就绪)。

预计:第 1–2 步是主要工作量,第 3–5 步各半天。
