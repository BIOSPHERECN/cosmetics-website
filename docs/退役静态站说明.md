# sites/* 五个静态站已退役(2026-08-18)

## 状态

| 目录 | 状态 |
|---|---|
| `sites/beauty2oem` `skin2oem` `medierba` `biosphere-ai` `biosphere-oralcare` | **已退役**,不再参与 `npm run build` |
| `sites/style-lab` | 保留 —— 风格评审用,`npm run build:lab` 单独构建 |
| `apps/web` | **线上唯一部署**,一个 Worker 按域名服务 5 个品牌 + `/bohui/` 后台 |

## 为什么退役

这 5 个目录是第一版:每站一个静态构建、内容写死在 `packages/core/src/content/*.ts`。
`apps/web` 上线后,内容真源搬到了 D1,运营在后台改一句话就生效 ——
静态站那套要改代码再发版,已经没有用武之地。

## 为什么现在才从构建里摘掉

今天加印尼语/马来语/法语时它们炸了:
`content/*.ts` 是 `Record<Locale, HomeContent>`,新增语种没有对应条目,
取 `content[locale].checklistTitle` 直接读到 undefined。

这暴露了真正的问题:**一份退役代码仍然卡在主构建的关键路径上**。
每加一个语种、每改一次共享组件,都要顺手维护 5 份不会上线的产物。
所以不是"给它补三份译文糊过去",是把它从构建里摘出来。

代码没有删 —— 万一要回看第一版的版式还在。要构建就跑 `npm run build:retired`,
但那之前得先给 `content/*.ts` 补齐新语种,或者把它的 `Record<Locale,…>` 改成可选。

## 主构建现在是什么

```
npm run build        # 只构建 apps/web —— 线上跑的就是它
npm run build:lab    # 风格实验室
npm run build:retired # 五个退役静态站(需先补内容语种)
```
