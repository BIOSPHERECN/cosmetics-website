# 标杆站实测 → 改造方案

> 2026-08-11。创始人指出「你的架构不是老板喜欢的」「别人是多层架构」「交付惨不忍睹」。
> 复盘发现:我按 PDF 的**摘要表**和自己的判断造结构,**没有真去看标杆站**——
> 违反了工作宪法第五条「没调研就做 = 不符合需求」。本文是补上的实地调研与据此的改造方案。
>
> 数据为浏览器内实测(计算样式 + DOM),非印象。

## 一、实测数据

### Intercos(PDF 钦定「代工厂官网信息架构首选」)

About us                        → Overview / History / 领导力与价值观 / The Group

Research & Innovation           → Overview / 技术与创新
Makeup, Skincare & Personal care→ Makeup / Skincare & Personal Care

**首页版块**:About us / What we do / 品类 / Research & Innovation /
Intercos Concept / Sustainability / People / **KEY NUMBERS(轮播)** / **WE ARE GLOBAL(世界地图)**

## 二、差距诊断(我 vs 标杆)

| 维度 | 标杆 | 我做的 | 判定 |
|---|---|---|---|
| 顶级导航 | 6–7 个,带二级 | **1 个** | ❌ 根本性缺失 |
| 标题字体 | 定制/授权显示体 | system-ui | ❌ 廉价感主因 |
| 标题字号 | 80–178px | 64px | ❌ 气势不足 |
| 正文字号 | 18–20px | 16px | ❌ 偏小 |
| 首屏 | 品牌宣言/动态 | 标题+段落+按钮 | ❌ 模板感 |
| 视觉素材 | 图片/视频/地图 | **零** | ❌ 空 |
| 法务页 | Privacy/Legal | 无 | ❌ 出海必备 |

### 我自己设的两个枷锁,是根因

1. **「零外链所以只用系统字体」** —— 结论下错了。正确解法是**自托管开源字体**
   (SIL OFL 协议可商用),字体文件放自己域名,外部请求仍然是 0,但字体有性格。
2. **「没有实拍就什么图都不放」** —— 过度收紧。PDF 禁的是「素材库摆拍图冒充自家车间」,
   没禁装饰性图形。可用生成式图形(Canvas/CSS)建立视觉体系,不涉及任何版权与真实性问题。

### 另外两处「AI 生成感」(对照 artifact-design skill 自查)

- **并列内容用了 01/02/03 编号** —— 该 skill 明确:编号只在内容真是序列时才用。
  品类矩阵的四项是**并列**能力,不是步骤,编号纯属装饰。已列入待改。
- **圆角卡片 + 顶部强调条** —— 该 skill 把这个组合直接列为要避开的套路。我的品类矩阵正是它。

## 三、改造方案

### A. 排版重做(优先级最高,投入产出比最大)
- 自托管 2 款 SIL OFL 字体:一款压缩显示体(标题)+ 一款几何无衬线(正文)
- 字号阶梯上调:正文 16 → 18px;首屏标题 64 → 96–140px
- 字体文件 subset 后内联/自托管,外部请求保持 0

### B. 信息架构重做:1 个导航项 → 6 个顶级 + 二级
```
关于我们   → 集团概况 / 发展历程 / 工厂与产能 / 可持续
能力与服务 → 总览 / 化妆品制造 / 品牌孵化 / 包材方案
研发创新   → 总览 / 技术与配方 / 实验室与检测
产品品类   → 护肤 / 彩妆 / 洁护 / 口腔
资讯       → 新闻 / 行业观察
联系我们   → 询盘 / 招聘
页脚       → 隐私政策 / 法律声明 / 网站地图
```

### C. 视觉体系(不用素材库图,也不做空页)
- 生成式装饰图形建立品牌视觉语言
- 全出血色场 + 超大字组成版面节奏,而非一路通栏色块堆叠
- 数字区参照 Intercos 的量级写法(`>550` / `~5500`),不编精确值

### D. 保留不动的(已验证有效,不推翻重来)
- 三层令牌架构(一套模板撑 20 套风格)—— 这是我们独有的效率优势
- 零 JS / 零外链 / 四语 / WCAG AA 452 项零不达标 / CI 自动部署
- 收录闸门(未核实数据不被抓取)
